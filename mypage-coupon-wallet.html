내 쿠폰함 Coupon Wallet

받으신 쿠폰번호나 할인코드를 등록해 두면 예약할 때 찾기 쉽습니다.

쿠폰번호든 할인코드든 이 칸에 넣으시면 아래 알맞은 구획으로 들어갑니다.

개발 노트 (dev handoff)

  • 목록 = USER_COUPON_WALLET 에 담은 것 + tbl_coupon.customer_sn 가 본인인 기발급분. 두 소스를 합쳐 정렬.
  • 등록 입력은 CouponService.findByCouponNo() → 없으면 DiscountCodeService.findByDiscountCode() 순으로 조회. 입력값은 trim() + 대문자 정규화 후 비교.
  • 결제 검증 로직은 변경하지 않는다. 쿠폰함은 보관 전용이며 사용 가능 여부를 막지 않는다.
  • 양도: 쿠폰번호를 알려주면 그대로 사용 가능. [복사] 버튼이 양도 경로. 받은 사람도 자기 쿠폰함에 등록 가능.
  • 남이 먼저 사용한 경우 → is_use=1 이므로 사용완료 로 표시. 사용자 정보는 노출하지 않는다.
  • 적용 서비스 표기: 쿠폰은 tbl_coupon_group.service1..10, 할인코드는 EVENT_DISCOUNT_CODE.SERVICES 비트마스크 — 두 방식을 공통 라벨로 정규화 필요.
  • 할인코드는 기간이 2종(START_AT/END_AT = 코드 유효기간, DELIVERED_FROM/BY = 배송일 조건). 둘 다 표기.
  • 쿠폰함에서 빼기는 고객이 직접 등록한 건에만 노출. 계정으로 이미 발급된 건은 뺄 수 없다 (뺄 대상이 tbl_coupon 원본이 되어버리므로).
  • 빼기는 USER_COUPON_WALLET 행 삭제일 뿐, 쿠폰 자체는 그대로 살아 있다.
  • 정렬: 사용 가능 = 만료 임박순, 사용완료·만료 = 최근순.
  • 만료 14일 이내면 사용기한 옆에 남은 일수를 붉게 표기. 일수 계산은 KST 자정 기준 — 고객 기기 시간대로 계산하면 하루 어긋난다.
  • 모든 날짜는 KST 기준으로 표기.
  • 구획은 결제화면과 1:1로 맞춘다. 결제화면 입력칸이 #{discount.coupon}(쿠폰) 과 #{discount.partner.code}(할인코드/파트너코드) 두 개이므로 쿠폰함도 같은 이름, 같은 순서로 나눈다. 결제화면 라벨이 바뀌면 여기도 같이 바꿔야 함.
  • 표본 쿠폰의 이름과 조건은 2026-09-15 CS Live Reference 시트 실측값. 쿠폰번호만 가짜 (이 저장소는 공개).
  • ⚠ 시트는 service1~5(SDD·RS·USD·ICD·GCD)만 미러링하므로 표본의 적용 서비스는 일부만 검증됨. service6~10(DDD·BF·ISS·KD·D2D)과 할인코드의 할인율은 DB 직접 확인 필요함.
